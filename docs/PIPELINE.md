# 六步流程和数据契约

## 设计原则

六个步骤都有独立的输入、输出和来源签名。原始 PDF、原始 OCR 与模型响应保留；正式勘正通过台账重建，不直接编辑带校验和的缓存。每一条阶段状态和实际文件路径写入工作目录的 `workflow.json`。重新选择模型或更换有效结果会产生新的审查/应用版本，保留已有产物。

流程以生成可顺畅阅读的简体电子书为目标。独立模型提供额外判断，不是绝对可靠的裁决器。未能确定或相互冲突的部分保留原文。

## 1. OCR、结构与疑点

输入为 PDF 和书籍配置。`source_format=structure` 使用可选 PP-StructureV3 后端按明确页码识别，支持 GPU。逐页结果带来源页码和内容签名；同后端、输入和配置的已完成页可复用。`source_format=legacy` 直接导入每行一个页记录的 JSONL：

```json
{"page":1,"items":[{"text":"识别文字","box":[60,100,500,160],"score":0.8}]}
```

框坐标对应 PDF 按 `ocr_scale` 渲染后的像素；页码从 1 开始。结构后端可将原始 OCR 行恢复到版面区域内的阅读顺序。页码、页眉、正文、图片等角色可由书籍配置调整。章节、脚注和跨页连接需要显式配置，不能仅凭 OCR 分数推断。

`01-ocr/` 中的主要文件为：

- `raw_pages/`、`layout_json/`、`corrected/`：带校验和的阶段快照。
- `review/flagged_lines.csv`：低置信度、空识别、异常引号、候选字符、重复等规则筛选。
- `review/reviewed_lines.csv`：正式勘正台账。
- `book/book_structured.md`、`book/source_map.json`：繁体草稿和段落来源映射。

OCR 置信度并非校准过的准确率，规则筛选也会漏掉高置信度错误，因此还保留第 4 步的补漏检查。

## 2. 主模型视觉复核

按全部疑点块准备原图裁片、原文和来源签名，调用 `AI_*` 对应的图文模型。只提出图像支持的最小修改。返回值必须符合块 ID、唯一原文片段、不重叠编辑和修改范围上限，否则只保留原始响应，不导入正文。

输出位于 `02-vision/<version>/`，包括 `pilot.json`、`images/`、`results/`、`model_suggestions.csv` 与 `summary.json`。保留 `pilot.json` 文件名是为了兼容原有复核工具，不表示这一步只做抽样。

## 3. 独立视觉模型复核与正式导入

自动导入只限可确定的字形等价变化：ASCII 全半角折叠及 OpenCC `t2s` 后文本完全一致。程序不会用“模型说它很确定”来自动批准字词改变；也不使用会把上标 `²` 变成普通数字 `2` 的广义 NFKC 等价规则。原文正确、不输出正文的块保持原有处理。

其他修改、首轮不确定以及无有效首轮回答的块进入独立视觉复核。`JUDGE_*` 必须与主模型的服务/模型标识不同。任务含原文、候选和对应原图，返回：

```json
{"task_id":"p0001-b0000","verdict":"approve","edits":[],"reason":"独立复核依据"}
```

- `approve`：原样认可首轮最小勘正；不能在批准时偷偷改成另一候选。
- `revise`：独立模型看图后提出新的最小勘正，仍须通过原文定位及范围校验。
- `reject`：不采纳修改，保留已有原文。
- `uncertain`：证据不足，保留已有原文。

结果保存在 `03-judge/<version>/`。加 `--apply` 后，导入 `03-reviewed/<version>/review/reviewed_lines.csv`，保留既有人工勘正并按块合并。正常流水线重建校验和、应用清单和来源映射，生成繁体 Markdown，再通过 OpenCC 生成简体 Markdown；不会直接改缓存。

## 4. 全文保守补漏

输入为第 3 步的简体 Markdown。冻结为 `source.md` 后，默认将全文分成最多约 6000 字符的核心区间，并带前后各 500 字符上下文；核心区间连续、无遗漏。仅报告起点属于本段核心区间的问题，重叠上下文用于理解。

范围仅限前三步漏下、明确妨碍阅读的机械错误。不润色，不改译法，不统一术语，不改事实、逻辑、观点或旧译名；能理解的拗口译文不改。没有原图时不猜补缺字。意见包含精确引用、来源页码、行号、字符位置和可选的最小修补。

输出为 `04-text/<version>/report.md`、`issues.jsonl`、`issues.csv` 与 `evaluation_tasks.jsonl`。引文必须在输入上下文中唯一精确匹配。位置是冻结文本中从零开始的 Python Unicode 字符下标，左闭右开；不是 UTF-8 字节或 JavaScript UTF-16 位置。

这一步不修改正文。低影响、术语统一等超范围意见会被过滤。无法定位的返回项、模型截断或 `more_issues=true` 保持未完成状态。覆盖全文不等于模型发现了全部错误，也不代表每次推理同时看到了远处章节。

## 5. 独立文本复核与最小应用

任务含源文本、相邻上下文、首轮意见和原文位置，复核模型仍受相同“只补漏”范围限制。可以用 `--judge-prefix TEXT_JUDGE` 为此阶段配置不同于视觉复核的文本模型。

接口返回 `task_id`、`approve/reject/uncertain`、理由和空 `edits`。它只能决定已有候选是否应采纳，不得引入新的大范围修改。意见成立但没有确定的最小替换时仍保留原文。来自独立导出模板的 `agree/disagree/uncertain` 可供外部评测使用；内置收费复核接口使用上述统一契约，不混用两种结构。

应用前再次核对源 Markdown 哈希和每个原文片段。通常原片段与替换各限 16 字，删除重复的原片段最多 40 字；禁止插入新链接、图片、代码或跨行改写。相同修补只应用一次；不同修补重叠时全部保留原文并记入冲突台账。

输出位于 `05-final/<version>/book_simplified.md`、`images/` 和 `text_patch_ledger.json`。原始简体稿、原始 OCR 和繁体稿都保留。此处文本修补有自己的字符级台账，不伪装成原始 OCR 数据已被修改。

## 6. EPUB 与验收

第五步可选 `--source-images`，改用主模型将第四步的全部候选逐项与原图比对。确定且有图像依据的最小修补自动导入；其余留原文，并导出下一阶段队列。这条路线不要求独立模型，不将同模型自审称为独立评测。完整契约及独立命令见 [SOURCE_REVIEW.md](SOURCE_REVIEW.md)。

从第 5 步的最终简体 Markdown 直接调用 Pandoc；不会重新从繁体稿转换并覆盖第 5 步的修补。封面来自 PDF 配置页，目录按章节配置生成，正文图像随 EPUB 打包。

产物位于 `06-epub/<version>/book.epub`，附构建来源和审计报告。检查包括 ZIP 顺序/CRC、EPUB 元数据、导航、spine、资源、内部链接、锚点和章节数；部分选页会标记为 `partial_book`。短段落等信息仅是候选提示，不阻止按阅读目标交付。

最终路径在工作目录 `workflow.json` 的 `artifacts.epub`。包检查通过并不表示逐字校准、模型无遗漏或所有阅读器的样式都相同。
